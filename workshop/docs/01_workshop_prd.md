# VibeCoding 模板開發工作流 Workshop — 教學規劃文件

> **版本:** v2.0 | **更新:** 2026-06-08 | **狀態:** 草稿
> **v2.0 重點:** 示範專案改為「GeminiChat 串流聊天機器人」— 更快、成品更亮眼

## 1. 教學總覽

| 項目               | 內容                                                               |
| :----------------- | :----------------------------------------------------------------- |
| **課程名稱** | VibeCoding 模板實戰 Workshop：用 Claude Code 跑完一個專案          |
| **示範專案** | GeminiChat — 串流式 AI 聊天機器人（FastAPI + Gemini + 單頁前端）  |
| **總時長**   | 約 60 分鐘（含操作演練；核心開發循環壓到 ~20 min）                 |
| **目標受眾** | 已會基本程式開發，想學 AI 輔助開發工作流的開發者                   |
| **前置需求** | 已安裝 Claude Code CLI、Python 3.11+、uv、Git、一組 Gemini API Key |
| **教學模式** | 企業內訓：講師操作示範 + 學員同步跟做                              |

### 為什麼從 Todo 換成 Chatbot？

| 維度                   | 舊版 TaskFlow（Todo）          | 新版 GeminiChat（Chatbot）                                    |
| :--------------------- | :----------------------------- | :------------------------------------------------------------ |
| **開發速度**     | 全 CRUD + React 建置，~25 min  | 單一串流端點 + 單頁前端，~20 min                              |
| **視覺衝擊**     | 列表增刪改                     | **逐字串流輸出**（像 ChatGPT 打字效果）                 |
| **成品「強度」** | 標準練習作                     | 一個能真聊天的 AI 產品，學員會想拿去改                        |
| **前端負擔**     | React + Vite + Tailwind 建置鏈 | 單一 `index.html` + 原生 JS，零建置                         |
| **連結模板能力** | 一般                           | 串到 `cost-aware-llm-pipeline`、`mcp-builder` 等 LLM 技能 |

## 2. 教學目標與 OKRs

### 背景與痛點

| 痛點             | 說明                                           |
| :--------------- | :--------------------------------------------- |
| AI 工具碎片化    | 開發者用 AI 寫程式但缺乏系統化流程，品質不穩定 |
| 文件驅動斷裂     | 需求 → 設計 → 實作之間缺乏可追蹤的連結       |
| 品質把關缺失     | 沒有自動化的 Code Review、測試覆蓋率門檻       |
| 新手不知從何開始 | 模板功能多，但缺乏引導式學習路徑               |

### OKRs

| Objective                  | Key Result                                                                 | 衡量方式 |
| :------------------------- | :------------------------------------------------------------------------- | :------- |
| 學員能獨立使用模板開發專案 | 80% 學員在課後能跑通 `/task-init` → `/task-next` → `/tdd` 完整循環 | 課後問卷 |
| 理解 AI Agent 協作模式     | 學員能說出至少 3 個 Agent 的用途與觸發時機                                 | 隨堂問答 |
| 建立文件驅動開發觀念       | 學員能解釋 PRD → WBS → 實作的流程邏輯                                    | 課後作業 |
| 理解任務分級的價值         | 學員能判斷一個任務該走 quick / standard / critical                         | 隨堂問答 |

## 5. 課程大綱與允收標準

### Chapter 1: 認識模板（10 min）

| ID    | 內容                                                         | 教學方式      | 允收標準                |
| :---- | :----------------------------------------------------------- | :------------ | :---------------------- |
| C1-01 | VibeCoding 模板解決什麼問題                                  | 講述 + 對比圖 | 學員能說出 3 個痛點     |
| C1-02 | 5 大擴展機制速覽（Hook / Command / Skill / Agent / Context） | 架構圖        | 學員能區分 5 種機制     |
| C1-03 | Agent 編排劇本：主動委派 + handoff 接力                      | 流程圖        | 學員理解 agent 如何串接 |
| C1-04 | 目錄結構導覽 + statusline 能量條                             | 終端機展示    | 學員知道去哪找設定      |
| C1-05 | 環境準備：複製模板 + Gemini API Key + .mcp.json              | 同步跟做      | 學員本機環境就緒        |

**講師備註：**

- 用「沒有模板 vs 有模板」的對比開場，製造動機
- 展示模板目錄時用 `tree` 指令，但只展開第一層，避免資訊過載
- 順手秀一下 statusline 的 agent 計數能量條（改 `statusline.sh` 頂部 `BAR_STYLE` 可切樣式，`bash .claude/statusline.sh preview` 即時預覽），作為「模板會自己觀測自己」的彩蛋
- Gemini API Key 設定可提前準備好 `.env` 範例檔，節省時間

### Chapter 3: 開發循環 — 核心（20 min）

整個 Workshop 的核心，示範 3 輪「取任務 → 規劃 → TDD → 審查」循環，並體驗三種任務 lane。

#### 第 1 輪：後端串流 API（standard，8 min）

| ID    | 內容                                         | 展示重點                                                          |
| :---- | :------------------------------------------- | :---------------------------------------------------------------- |
| C3-01 | `/task-next` 取得第一個任務 + 選 standard  | WBS 自動選優先任務、推薦模式                                      |
| C3-02 | `/plan` 建立實作計畫                       | **planner agent** 分析串流架構、依賴、風險                  |
| C3-03 | `/tdd` 測試驅動開發                        | **tdd-guide agent** RED → GREEN → IMPROVE（mock Gemini）  |
| C3-04 | 展示測試從紅變綠                             | 強調「先寫測試」的紀律                                            |
| C3-05 | 打開 FastAPI `/docs` + 用 curl 看 SSE 串流 | 寫完 API 就有互動文檔；串流即時輸出                               |
| C3-06 | `/review-code` 程式碼審查                  | **code-quality-specialist** 抓出問題（如 API key 外洩風險） |
| C3-07 | git commit                                   | conventional commits 格式                                         |

**講師備註：**

- 第 1 輪最詳細，每個指令都暫停解說
- `/plan` 產出後停下來，讓學員讀計畫，建立「AI 規劃 → 人類審核」的觀念
- `/tdd` 時刻意讓測試先失敗（RED），截圖/錄影這個紅色輸出，視覺衝擊最強
- 串流端點用 `curl -N http://localhost:8000/api/chat` 展示 token 逐塊吐出 — 這是後端的第一個 wow

#### 第 2 輪：前端聊天 UI（standard，8 min）

| ID    | 內容                                        | 展示重點                                   |
| :---- | :------------------------------------------ | :----------------------------------------- |
| C3-08 | `/task-next` 取下一個任務                 | 自動跳到前端任務                           |
| C3-09 | `/ui-style` +（首次）`/plan` + `/tdd` | UI 設計規範自動套用                        |
| C3-10 | 瀏覽器查看成果                              | **逐字串流顯示** — 全場最強視覺衝擊 |
| C3-11 | 即時對話一輪                                | 真的能聊天，多輪 context 生效              |

**講師備註：**

- 第 2 輪節奏加快，重點放在「重複流程的肌肉記憶」
- 瀏覽器打開聊天頁、輸入訊息、看 AI 一個字一個字吐回來 — **這是整堂課的高潮**，務必確保 server + API Key 正常
- 單頁前端零建置，啟動快；若時間緊迫可預先準備好骨架做增量

#### 第 3 輪：quick lane — 加角色設定 / 修 Bug（4 min）

| ID    | 內容                                            | 展示重點                                            |
| :---- | :---------------------------------------------- | :-------------------------------------------------- |
| C3-12 | `/task-next` 選 **quick** 模式          | 小修改不走完整 plan/tdd                             |
| C3-13 | 直接加「系統提示」讓 bot 變身（如「海盜語氣」） | quick lane 的快                                     |
| C3-14 | 刻意引入 build error →`/build-fix`           | **build-error-resolver (Haiku)** 最小差異修復 |
| C3-15 | `/verify` 自動跑 quick profile                | 數秒完成                                            |

**講師備註：**

- 改個 system prompt 就讓 bot 換人設，互動性強、學員會笑
- 刻意犯錯比完美示範更有教學效果 — 打消學員的恐懼感

## 6. 示範專案規格 — GeminiChat

### 功能範圍

| 模組               | 功能                                             | 優先級 | 對應教學章節       |
| :----------------- | :----------------------------------------------- | :----- | :----------------- |
| **後端串流** | `POST /api/chat` 以 SSE 逐字串流回 Gemini 回覆 | Must   | Ch3 第 1 輪        |
| **對話歷史** | 接收 messages 陣列，維持多輪 context             | Must   | Ch3 第 1 輪        |
| **系統提示** | 可設定角色/人設（system instruction）            | Should | Ch3 第 3 輪        |
| **前端 UI**  | 單頁聊天介面 + 對話氣泡 + 逐字串流顯示           | Must   | Ch3 第 2 輪        |
| **互動細節** | loading 狀態、Enter 送出、清除對話               | Should | Ch3 第 2 輪        |
| **安全強化** | API Key 環境變數 + 簡易 rate limit               | Could  | critical lane 選做 |

### 技術選型

| 層級     | 選擇                                               | 理由                                                             |
| :------- | :------------------------------------------------- | :--------------------------------------------------------------- |
| 後端語言 | Python 3.11+                                       | 講師熟悉、語法直覺、學員易讀                                     |
| 後端框架 | FastAPI                                            | 自帶 OpenAPI 文檔、型別提示、async 與 StreamingResponse 原生支援 |
| LLM SDK  | `google-genai`（Gemini）                         | 官方 SDK，支援 `generate_content_stream` 串流                  |
| 串流傳輸 | SSE（`StreamingResponse` / `sse-starlette`）   | 瀏覽器原生 `EventSource` 即可消費，逐字顯示效果佳              |
| 前端     | 原生 HTML + CSS + JS（單頁）                       | 零建置、啟動快，demo 節奏最順                                    |
| 設定管理 | `python-dotenv` + `.env`（`GEMINI_API_KEY`） | 標準做法，順帶教安全規範                                         |
| 後端測試 | pytest + httpx（AsyncClient），mock Gemini         | Python 測試標準、避免 demo 打真 API 計費                         |
| 樣式     | 原生 CSS 變數（Apple 風格 fallback）               | 與模板 `ui-design.md` fallback 契合，零依賴                    |
| 套件管理 | uv                                                 | 模板強制：`uv add` / `uv run`                                |

### 環境變數

```
# .env（不進 git，加入 .gitignore）
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-2.0-flash   # 求快用 flash 系列
```

### 明確不做

- 使用者帳號 / 登入授權
- 對話持久化到資料庫（記憶體保存即可）
- 檔案 / 圖片上傳、多模態
- 雲端部署
- 串接向量資料庫 / RAG（課後延伸題）

## 8. 教學風險與對策

| 風險                                      | 可能性 | 影響 | 對策                                                 |
| :---------------------------------------- | :----- | :--- | :--------------------------------------------------- |
| Gemini API Key 過期 / 額度不足 / 地區限制 | 中     | 高   | 預備離線錄影；測試以 mock 為主，不打真 API           |
| 串流端點在某些 proxy / 防火牆被緩衝       | 中     | 中   | 後端設 `X-Accel-Buffering: no`；備用直接 curl 展示 |
| 學員環境差異大（Windows/Mac/Linux）       | 高     | 中   | 統一用 uv；提供預錄影片對照                          |
| MCP Server 連線失敗                       | 中     | 低   | 只依賴核心功能，MCP 作為加分項展示                   |
| `/task-init` 產出不如預期               | 低     | 中   | 準備好一份「標準答案」CLAUDE.md 可直接替換           |
| 單堂時間不夠                              | 中     | 中   | Chapter 5 可彈性縮減，優先保 Chapter 2-3             |

## 9. 課後延伸

### 作業建議（學員自行練習）

1. **初級：** 用模板建立一個「翻譯小幫手」chatbot，跑完 `/task-init` → `/task-next` → `/tdd` 循環
2. **中級：** 為 GeminiChat 加上「對話歷史持久化」（存 SQLite）+ 「切換多個角色預設」
3. **進階：** 為 GeminiChat 加上 RAG（讀取一份 PDF/文檔後問答）或串 `mcp-builder` 把它變成一個 MCP tool

### 推薦學習路徑

```
Workshop 完成
    │
    ├── 想深入 Agent 機制 → 閱讀 .claude/agents/ 下的 14 個定義檔 + rules/agent-orchestration.md
    ├── 想客製化規則    → 閱讀 .claude/rules/ 並修改或新增
    ├── 想擴充 Skills   → 瀏覽 custom-rule&skill/skills/ 的 94+ 選項
    ├── 想優化 LLM 成本 → 使用 cost-aware-llm-pipeline skill
    ├── 想做完整專案文件 → 使用 /docs-init --full 走 VibeCoding 16 模板
    └── 想建 MCP Server → 使用 mcp-builder skill
```
