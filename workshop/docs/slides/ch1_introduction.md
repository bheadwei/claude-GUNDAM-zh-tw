## Slide 6: CLAUDE.md — 專案說明書

```
📄 CLAUDE.md
┌─────────────────────────────────────────────┐
│  特性：每次對話開頭自動載入                  │
│  位置：專案根目錄                            │
│  類比：給新員工的 Onboarding 文件            │
│                                             │
│  內容：                                      │
│   • 專案是什麼、解決什麼問題                  │
│   • 技術棧（語言、框架、DB）                  │
│   • 目錄結構與重要檔案                       │
│   • 開發流程約定                            │
│   • 嚴禁事項（如：不可碰 prod DB）           │
│                                             │
│  寫得好的 CLAUDE.md = AI 一進來就懂專案       │
└─────────────────────────────────────────────┘
```

**講師口述：** CLAUDE.md 是專案層級的記憶體。AI 每次啟動都會讀。寫得好，AI 就不會問「這個專案在做什麼」、「為什麼這樣寫」這類本來該知道的事。`/task-init` 會幫你產一份。

## Slide 7: rules/ — 永遠載入的規則

```
📏 .claude/rules/
┌─────────────────────────────────────────────┐
│  特性：每次對話開頭自動載入（與 CLAUDE.md 並列）│
│  位置：.claude/rules/*.md                    │
│  類比：公司的員工守則                         │
│                                             │
│  範例（本模板有 15 條）：                    │
│   • coding-style.md     編碼風格             │
│   • testing.md          測試覆蓋率           │
│   • security.md         安全規範             │
│   • git-workflow.md     提交規範             │
│   • task-mode.md        任務分級             │
│   • interactive-qa.md   問答互動規則          │
│                                             │
│  特點：粒度小、可組合、可關閉個別規則          │
└─────────────────────────────────────────────┘
```

**講師口述：** rules 跟 CLAUDE.md 都是強制載入的，但 rules 是**橫切關注點**——適用於所有任務的通則（如安全、測試、風格），CLAUDE.md 是**專案專屬**內容。把它們分開讓規則可以跨專案複用。

## Slide 8: commands/ — 你的快捷指令

```
⚡ .claude/commands/
┌─────────────────────────────────────────────┐
│  特性：使用者輸入 /xxx 時觸發                │
│  位置：.claude/commands/*.md                 │
│  類比：終端機的 alias                        │
│                                             │
│  本模板提供 25 個指令：                      │
│   /task-init     專案初始化                  │
│   /task-next     取下一個任務                │
│   /plan          規劃實作                    │
│   /tdd           測試驅動開發                │
│   /review-code   程式碼審查                  │
│   /verify        全面驗證                    │
│   /agent-log     看 subagent 軌跡            │
│   /ui-style      選 UI 風格                  │
│   ...                                        │
│                                             │
│  本質：預設 prompt 模板，幫你省打字           │
└─────────────────────────────────────────────┘
```

**講師口述：** Commands 就是把常用 prompt 包裝成一個指令。它的內容其實就是一個 markdown 檔，告訴 AI「當使用者打 /tdd 時，照這個流程做」。你也可以自己寫，放到 `.claude/commands/` 就生效。

## Slide 9: agents/ — 專業 AI 同事

```
🤖 .claude/agents/
┌─────────────────────────────────────────────┐
│  特性：主 AI 委派子任務時呼叫                │
│  位置：.claude/agents/*.md                   │
│  類比：團隊裡的專科同事                      │
│                                             │
│  為什麼需要 Agent？                          │
│   • 隔離 context — 不污染主對話              │
│   • 專用工具 — 例如審查 agent 只給讀檔權限    │
│   • 模型分工 — Opus 想策略、Haiku 修小錯      │
│   • 平行執行 — 多個 agent 同時跑             │
│                                             │
│  例子：                                      │
│   planner（規劃）→ tdd-guide（寫測試）        │
│   → code-quality（審查）→ build-fix（修錯）   │
└─────────────────────────────────────────────┘
```

**講師口述：** Agent 是 Claude Code 最強大的設計。把任務委派給專業 sub-agent 後，主對話不會被一堆細節塞滿，而且每個 agent 用最適合的模型——Opus 想架構、Haiku 修 bug，又快又省 token。

## Slide 10: skills/ — 領域知識按需載入

```
🔧 .claude/skills/
┌─────────────────────────────────────────────┐
│  特性：AI 語意偵測，符合條件自動載入          │
│  位置：.claude/skills/<name>/SKILL.md         │
│  類比：手冊櫃 — 需要時才翻                    │
│                                             │
│  本模板的 7 個 skill：                       │
│   • postgres-patterns   寫 SQL 時自動載入     │
│   • database-migrations Schema 變更時觸發    │
│   • e2e-testing         寫 E2E 測試時觸發    │
│   • mcp-builder         做 MCP server 時觸發 │
│   • cost-aware-llm      AI 應用成本優化      │
│   • deep-research       多源研究             │
│   • project-docs        產 PRD/ADR 時        │
│                                             │
│  與 rules 差別：rules 永遠載入，skill 按需    │
└─────────────────────────────────────────────┘
```

**講師口述：** Skill 是一種「隱性觸發」的知識包。你不需要記得「我要做 DB migration 該載入哪個技能」，AI 會自己判斷。設計重點是**只放模型不知道的專案特定知識**——像 React 用法這種模型已經會的，不用做 skill。

## Slide 11: hooks/ — 事件自動化

```
🪝 .claude/hooks/
┌─────────────────────────────────────────────┐
│  特性：系統事件發生時自動執行 shell 腳本     │
│  位置：.claude/hooks/*.sh + settings.json     │
│  類比：Git hooks 或 GitHub Actions            │
│                                             │
│  事件類型：                                  │
│   SessionStart    啟動時             顯示模板提示 │
│   PreToolUse      呼叫工具前        權限檢查 │
│   PostToolUse     工具執行後        記錄、自動格式化 │
│   UserPromptSubmit 使用者送出       注入上下文 │
│   Stop / Notification               收尾通知 │
│                                             │
│  本模板用 hook 做：                          │
│   • 啟動時提示「TaskMaster Ready」            │
│   • 寫檔後自動更新時間追蹤                    │
│   • 偵測 Pencil 設計稿位置不合規              │
└─────────────────────────────────────────────┘
```

**講師口述：** Hooks 是 AI **不能拒絕執行**的副作用。AI 只負責決策，hook 負責落實——例如記錄時間、檢查路徑、更新狀態檔。重要的是 hook 直接執行 shell，AI 看不到也改不了。

## Slide 12: 6 大觀念對照表

```
觀念       觸發方式      生命週期    主要用途
──────    ──────────   ─────────   ─────────────
CLAUDE.md  自動載入       長駐 ctx    專案說明
rules      自動載入       長駐 ctx    跨專案通則
commands   使用者 /xxx   單次調用    封裝常用 prompt
```

**講師口述：** 一張表記住差異。**自動 vs 觸發、長駐 vs 按需、AI 內 vs AI 外**——這三條軸決定每個觀念的角色。今天會密集用到的是 commands 和 agents，其他在背景幫你工作。

## Slide 14: Agent 編排劇本 — 主動委派 + 接力

```
┌─────────────────────────────────────────────────┐
│  原則：有專家就委派，交棒靠 handoff 不靠記憶     │
│                                                 │
│   新功能的標準鏈：                               │
│                                                 │
│   planner → tdd-guide → code-quality            │
│        → test-automation →（critical）security   │
│                                                 │
│   每棒做完會：                                   │
│    1. 寫報告到 .claude/context/                  │
│    2. 對下一棒建 handoff（coordination/handoffs）│
│    3. hook 注入提示 → 主 AI 接手下一棒           │
│                                                 │
│   用 /agent-log 隨時看：誰跑過、留了什麼、交給誰  │
└─────────────────────────────────────────────────┘
```

**講師口述：** Agent 不是各跑各的，而是像接力賽。一棒做完會留下報告、把後續工作寫成「交接單」，模板的 hook 看到交接單就提示主 AI 接手下一棒。這就是為什麼一個 `/tdd` 跑完，常會自動接到審查、補測試。今天 Ch4 的 `/agent-log` 就能把整條軌跡攤開給你看。
