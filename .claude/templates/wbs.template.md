# WBS 格式（唯一來源）

> `.claude/taskmaster-data/wbs.md` 與 `wbs-archive.md` 的格式**只定義在這裡**。
> 會寫 WBS 的指令（`/task-init` `/task-add` `/task-next` `/verify` `/task-status`、
> `planner` agent）一律引用本檔，**不要在別處內嵌副本**——兩份範本會漂開，這個模板發生過。
>
> 本檔**不會被自動載入**，指令要寫 WBS 時才讀。歸檔**程序**的唯一來源是
> `.claude/commands/task-status.md` 的「WBS 歸檔」節；本檔只定義歸檔檔案長什麼樣子。

WBS 是**打開就能掌握專案狀態**的文件，不是工作日誌。判準：除了「任務」欄寫完整名稱，其他格子都只寫一行。
`post-write.sh` 會在寫入 `wbs.md` 時檢查格子長度（約 40 字，「任務」欄除外），超過會提醒（只提醒，不擋）。

## 2. 欄位規則

**每一格只寫一行。** 寫不下就代表它不屬於 WBS——依第 4 節搬到該去的地方，格子裡只留連結或 ID。

| 欄位 | 寫什麼 | 不寫什麼 |
|---|---|---|
| `#` | `<組>.<序>`，例 `13.2`。組與里程碑不必一一對應（M11 底下可以是 13.x）。**編號永不重用**，含已歸檔的 | — |
| 任務 | 完整任務名稱（動詞＋對象），**不縮寫、不截斷**；與 plan 標題一致 | 做法、驗收條件（那是 plan） |
| 狀態 | `✅ MM-DD`／`🔄 進行中`／`⏳ 待處理`／`🚫 阻塞`／`⏭️ 跳過` | 驗證數據、進度百分比、原因 |
| 優先 | `高`／`中`／`低` | — |
| 依賴 | 任務編號，逗號分隔；無則 `—` | 技術依賴（那是 plan） |
| 預估 | `4h`、`0.5h` | 實際耗時（`timelog.jsonl` 會算，歸檔時寫進 archive） |
| 負責 | **一個**人名，小寫（`alice`）；未指派 `—`。新建任務填 `—`，使用者指名時才填 | 多人並列、協作者、角色說明（分工細節寫 plan 或帳本）；從 commit 作者或備註推測的人名（指派是使用者的決定） |
| 連結 | `[計畫](plans/…)`・`[報告](…)`・`[帳本](plans/….progress.md)`・風險 ID（`R3`）；多個用 ` ・ ` 分隔；無則 `—` | 任何說明文字 |

**連結欄的生命週期**（雙向同步規範見 `plan-format` skill 的「與 WBS 的雙向同步」）：

| 時機 | 誰 | 連結欄變成 |
|---|---|---|
| 新建任務 | `/task-init`、`/task-add` | `—` |
| 產出 plan | `/plan`（`planner`） | 加上 `[計畫](plans/<id>-<slug>.md)` |
| 走執行型委派 | 主模型 | 加上 `[帳本](plans/<id>-<slug>.progress.md)` |
| 標 🚫 阻塞 | 標記者 | 加上風險 ID，並在「風險與阻塞」表新增或沿用該 ID |
| 歸檔 plan | `/verify` | 計畫與帳本改指 `plans/archive/…`（漏掉會變死連結） |

路徑相對於 `wbs.md` 所在的 `.claude/taskmaster-data/`：plan 寫 `plans/…`，報告寫 `../context/…`。

## 3. 「現況」區的重算規則

「現況」與檔頭的「總進度」是**衍生摘要**。任何指令寫完任務列之後，**同一次寫入**裡一併重算，
不要留到下次（打開看到的數字和下面的表對不上，比沒有摘要更糟）。

| 項目 | 怎麼算 |
|---|---|
| 總進度 | 分子＝✅ 任務數（含已歸檔），分母＝全部任務數 − ⏭️ 數（含已歸檔）。10 格長條，填滿格數 = round(比例 × 10) |
| 里程碑「進度」 | 同上算法，5 格長條＋`完成/總數`。已歸檔的里程碑改寫 `已歸檔 N 項` |
| 里程碑「狀態」 | 全部 ✅／⏭️ → `✅ 完成`；有 🔄，或已有 ✅ 但未全完成 → `🔄 進行中`；其餘有 🚫 → `🚫 阻塞`；否則 `⏳ 待處理` |
| 里程碑「目標日」 | **唯一不是算出來的欄位**——使用者定的。重算時沿用原值；要改日期就直接講或手改該格 |
| 已歸檔里程碑 | 連續的已歸檔里程碑併成一列（`M1–M10`）；只有一個就照寫名稱 |
| 進行中 | 所有 🔄 任務的 `編號 名稱` |
| 阻塞 | 所有 🚫 任務的 `編號 名稱 — <風險表的短描述>（<風險 ID>）` |
| 下一個 | 依 `/task-next` 的選法（依賴全 ✅ 的 ⏳ 任務中優先級最高者） |

三行摘要沒有內容時寫 `—`；超過 3 項時列前 3 項加「等 N 項」。

已歸檔的任務數直接取現況表「已歸檔 N 項」那一列，重算時不必每次讀 `wbs-archive.md`。
N 只算歸檔里程碑裡的 ✅（歸檔時就排除 ⏭️），所以它同時加進分子與分母。

## 4. 長內容該去哪裡

這是 WBS 變得無法閱讀的主因：格子被當成工作日誌寫。**寫之前先查這張表。**

| 想寫進格子的 | 改放到 | WBS 留什麼 |
|---|---|---|
| 驗證數據、執行結果（hit@5、延遲、測試數） | 評估報告（`context/<area>/`），或 plan 檔該階段的「驗收」 | 連結欄 `[報告](…)` |
| 進度、派工、commit SHA | 執行帳本 `plans/<id>-<slug>.progress.md` | 連結欄 `[帳本](…)` |
| 帶給下一任務的疑慮 | **下一任務** plan 檔的「風險與緩解」 | 不留（下一任務的 plan 已經有） |
| 選型與理由 | `context/decisions/` 或 ADR（`/adr`） | 必要時連結欄 `[ADR](…)` |
| 阻塞原因 | 本檔「風險與阻塞」表 | 狀態 `🚫 阻塞` ＋ 連結欄風險 ID |
| 任務等級（quick／standard／critical） | plan 檔 frontmatter 的 `mode:` | 不留 |
| 主機 IP、帳號、環境細節 | 部署文件或 `.env.example`（**秘密不進任何 md**） | 不留 |

> `post-write.sh` 的長度提醒附了這張表的簡短版。改這張表時同步那段訊息。

## 5. `wbs-archive.md` 版面

已完成的里程碑整段搬來（程序見 `/task-status` 的「WBS 歸檔」節）。任務表與 `wbs.md` 相同，
**多一個「實際」欄**——歸檔後仍要能回顧估準不準：

```markdown
# WBS 歸檔 — <專案名稱>

## M1 MVP（2026-06-01 ~ 2026-08-10）・ 12 項 ・ 預估 24.5h ／ 實際 27h

| # | 任務 | 狀態 | 優先 | 依賴 | 預估 | 實際 | 負責 | 連結 |
|---|---|---|---|---|---|---|---|---|
| 1.1 | 專案初始化 | ✅ 06-01 | 高 | — | 0.5h | 0h25m | — | — |
| 1.2 | auth middleware | ✅ 06-03 | 高 | 1.1 | 4h | 4h40m | bob | [計畫](plans/archive/1.2-auth-middleware.md) |
```

「實際」取自 `timelog.jsonl`；沒有資料就寫 `—`。「負責」從 `wbs.md` 原樣帶過來。

**欄位以各節自己的表頭為準。** 每個里程碑一節、每節自帶表頭；加入負責欄之前歸檔的節**原樣保留、不回填、不改表頭**（表頭多一欄而列沒補格，那一欄會整欄空白、後面欄位錯位）。所以讀這個檔的指令（`/task-add` 掃編號、`/time-log` 查任務、`/task-status --detailed`）要**依該節表頭找欄位**，不能假設固定位置。

## 6. 舊格式

沒有「現況」區的 `wbs.md` 是舊格式（欄位 `Plan`／`備註`，或連 `Plan` 欄都沒有）。
**轉換程序見 `/task-status` 的「舊格式轉換」節**——長內容依第 4 節搬出去，不能丟資料。
