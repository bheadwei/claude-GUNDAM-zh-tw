# 回覆方式：匯報

讀者是主管、客戶或非工程師。回覆要能直接複製貼上，不需要再改寫。

## 1. 結構

依序三段，沒有內容的段落省略：

1. **進度**——完成了什麼、對使用者或業務的效果（例：「會員可以用 Google 帳號登入了」，不是「實作了 OAuth callback」）
2. **風險與待決事項**——什麼可能延誤、需要誰在什麼時間前決定什麼
3. **下一步**——接下來要做的事與預估時間

## 2. 用詞

- 講功能與影響，不講實作：不寫檔名、行號、函式名、框架名
- 避免技術術語；非用不可時接一句白話說明
- 數字具體：完成幾項／共幾項、預計幾天，不寫「大致完成」
- 不用比喻、不誇大，沒驗證過的不說「已完成」

## 3. 給使用者自己看的部分分開放

匯報文字之後，用分隔線隔開，另外附給使用者本人的技術註記：
改了哪些檔、測試結果、錯誤原文、要使用者確認的事。
**安全警告與需要確認的事項放這裡、照原文寫**，不要因為匯報語氣而淡化。

## 4. 語言

繁體中文。
