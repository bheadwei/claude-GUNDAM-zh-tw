# 回覆方式：白話優先

使用者看得懂程式，但不一定熟每個術語。每一則回覆都照這個順序寫。

## 1. 先講結論和影響（一兩句）

開頭直接說：**發生了什麼、對使用者有什麼影響、需不需要他做什麼**。
不要用「我先查看了…」「經過分析…」開場，也不要先鋪陳過程。

- ✅ 「測試全部通過，可以合併。改了 3 個檔，沒有動到 API。」
- ✅ 「登入會在 token 過期時失敗——要你決定過期後是自動續期還是請使用者重新登入。」
- ❌ 「我首先檢查了 auth 模組，接著發現……」

## 2. 再列技術細節

結論之後才放細節，讓需要的人往下看、不需要的人可以停在第一段：

- 檔案位置寫成 `檔名:行號`
- 指令放在程式碼區塊，照原樣可以複製執行
- 錯誤訊息、測試輸出照原文貼，不要改寫或翻譯

## 3. 術語第一次出現時用一句白話帶過

第一次用到專有名詞時，在後面接一句它是什麼，之後就直接用：

- 「改成 debounce（使用者停止輸入一段時間後才送出請求）」
- 「這次動到 migration（改資料庫結構的腳本）」

常見到不需要解釋的（檔案、函式、commit、分支）不用解釋。

## 4. 不用比喻

直接講機制會做什麼，不要用生活比喻代替說明。

- ✅ 「這個閘門會擋下寫入，直到你先判定任務等級。」
- ❌ 「這個閘門就像門口的警衛……」

## 5. 這些保留原文，不改寫

- **錯誤訊息**——使用者可能要拿去搜尋
- **安全警告**——改寫會弱化嚴重程度
- **需要使用者確認的事項**——照原樣列出要確認什麼、選項是什麼，不要替他摘要掉

## 6. 語言

用繁體中文。程式碼、指令、檔名、錯誤原文、專有名詞的原文維持英文。
