## 2. 分層決定

依 `writing-extensions` 的五層表依序問，第一個「是」就決定層級。

| 機制 | 層 | 判斷依據 |
|---|---|---|
| 掃程式碼產出骨架（模組、依賴邊、路由數） | **Script**：新的 `.claude/scripts/overview-scan.sh` | 確定性的資料轉換、0 token。從 `overview.sh` 拆出來，因為 `overview.sh` 已經 1103 行，而掃描是另一個職責（拆檔看職責）。產物是 `overview/skeleton.json`（不進 git） |
| 骨架、5.5、WBS、notes 合併成 data.js；落差報告 | **Script**：`overview.sh` | 同上 |
| 何時重掃 | **Hook**：`post-write.sh`（既有的 PostToolUse 接線） | 時機機器判斷得出。寫程式碼檔也觸發，但 30 秒內只觸發一次；節流只用 bash 內建（`printf '%(%s)T'`、`read`），在視窗內完全不開子行程 |
| 白話說明 | **Agent**：documentation-specialist（既有） | 要獨立 context 讀大量程式碼 |
| 說明的寫作標準 | **附屬檔**：`.claude/skills/project-docs/module-notes.md`，由 agent 定義明寫路徑去讀 | 寫的人是固定的 agent，**不需要靠 description 被想起來**，所以不開獨立 skill |

| 何時寫說明 | **Command**：`/task-status`（既有）用 AskUserQuestion 問 | 花 token、送程式碼給模型，必須由使用者決定；使用者偏好整合進既有指令、不新增指令 |
| 畫面 | 範本檔：`.claude/templates/overview/index.html` | 沿用現狀 |
| 欄名常數、頁面大小、token 化、沒有外部網址 | **Script**：`check-counts.sh` | 安靜失效型的問題，只有 CI 擋得住 |

**刻意不做的：**

- 不新增 rule、command、agent
- 不改 `using-taskmaster`（常駐注入，這個功能對路由沒有幫助）
- 不新增 hook 檔或事件接線

**skill 是不是「說明層品質」的正確載體？不是唯一的載體。** skill（或附屬檔）負責「怎麼寫好」：寫作標準、範例、禁用詞。
但「保證」要靠機器驗證，加上寫入當下的 hook 回饋。
只放 skill 的話，寫錯了也沒有人知道——這正是模板踩過四次的同一類錯誤。

## 3. 骨架掃描（`overview-scan.sh`）

### 3.1 演算法

1. **檔案清單**：`git -c core.quotepath=off ls-files -z --cached --others --exclude-standard`（1 個行程）。
   排除 `.claude/`、`docs/`、測試目錄（只計數，不當模組）、vendor 與產物目錄。
   `project.json` 的 `overview.scan.exclude` 可以再加排除項
2. **套件邊界**：非根目錄裡有 `package.json`、`pyproject.toml`、`go.mod`、`*.csproj`、`pom.xml`、`build.gradle*`、`Cargo.toml` 的目錄，視為一個套件
3. **原始碼根**：每個套件（或 repo 根）底下的 `src/`、`app/`、`lib/`、與套件同名的目錄；都沒有就用套件根本身
4. **模組**：原始碼根底下第一層含程式碼的子目錄。
   - 某個目錄占全部檔案 40% 以上、而且有兩個以上含程式碼的子目錄 → 再往下切一層
   - 檔案少於 2 個的目錄併入「其他」
   - 總數上限 `OVERVIEW_MAX_MODULES`（預設 40），也可以用 `overview.scan.roots` 或 `overview.scan.depth` 覆寫
5. **模組 id**：取路徑最後一段轉成 kebab-case；撞名時加上父層前綴（`api`、`admin-api`）。同一份路徑永遠得到同一個 id
6. **依賴邊**：用一次 `git grep -z -n -I -E '<各語言的 import 樣式聯集>'` 掃完，再交給 awk 依副檔名解析：

   | 語言 | 解析方式 |
   |---|---|
   | Python | `from x.y import`／`import x`，加上相對 `from .x` |
   | TS／JS | `from '…'`、`require('…')`、`import('…')`，只解析相對路徑與 `@/`（對應 `src/`） |
   | Go | 依 `go.mod` 的 module 前綴 |
   | Java／Kotlin | 同一次 grep 一起收 `package`／`import`，建立 package→模組對照 |
   | C# | 同一次 grep 一起收 `namespace`／`using`，建立 namespace→模組對照 |

   結果彙總成 `{from, to, weight: import 次數, source: "import"}`。對不到任何模組的 import（第三方套件）先丟掉，外部系統那一欄留到階段 6 選做
7. **路由**：同一次 grep 一起比對各框架的路由寫法：
   - FastAPI／Flask：`@app.get(`、`@router.post(`、`@app.route(`
   - Express：`app.get(`、`router.post(`
   - Spring：`@GetMapping`
   - ASP.NET：`[HttpGet`、`[Route(`

   每個模組記路由數，並保留前 20 條的 `METHOD path`
8. **快取**：`skeleton.json` 帶 `key = HEAD sha + 工作區改動清單的雜湊`（改動清單 `overview.sh` 本來就會收）。key 沒變就不重掃

**行程預算**：`ls-files` 1、`git grep` 1–2、awk 2–3、jq 1，**合計 12 個以內**。
目標是 5,000 檔的 repo 在 Windows Git Bash 背景執行 3 秒內完成、Linux 1 秒內完成。
檔案數超過 `OVERVIEW_SCAN_MAX_FILES`（預設 20000）時，只做目錄層級的骨架、不掃依賴邊，並加一則 notice。

**相容性鐵律：**

- jq 只用 1.6 的語法（不用保留字當變數名，不用 1.7 之後才有的內建函式）
- awk 以 `LC_ALL=C` 逐位元組處理，JSON 跳脫一律交給 jq
- 路徑一律用 `-z` 分隔，參考 `learned/2026-11-04-jq-windows-non-ascii-path.md`

### 3.2 與架構文件 5.5 合併（既有專案不能退化）

| 情況 | 行為 |
|---|---|
| 5.5 有 `id`、`路徑` 欄而且有效 | 路徑對得上的掃描模組，一律改用 5.5 的 `id`、名稱與分組（**WBS 既有的模組對應全部保留**）。5.5 有、但路徑對不到任何檔案的 → 列入落差「文件寫了、程式沒有」，地圖上畫虛線框。掃到、5.5 沒寫的 → 照畫，`source: "scan"`，列入落差「程式有、文件沒寫」 |
| 沒有架構文件、或格式不合（for-query） | 完全用掃描結果。5.1 裡對不到模組的節點（C4 的使用者、LDAP、MSSQL）**不畫成灰框** |
| 架構文件帶 draft 標記 | 不拿它覆寫，地圖照樣畫。**這是行為變更**：舊測試第 3-19 條要改 |
| 找架構文件的順序 | 加入 `docs/**/*architecture*.md`（for-query 把文件放在子資料夾）。`project.json` 的 `overview.architectureDoc` 覆寫仍然優先 |

名稱的優先序：5.5 → `module-notes.md` → 目錄名。
分組的優先序：5.5（5.1 的 subgraph）→ notes 的「分組」欄 → 原始碼根或套件名。

### 3.3 任務對到模組

WBS 有模組欄就照舊。沒有、或填 `—` 時，用 plan 的 `files:` 加上該任務的 diff 推斷，
結果標 `inferred: true` 與推斷依據（`plan-files` 或 `diff`），畫面上用虛線的任務標記顯示。

data.js 新增 `drift`，`overview.md` 新增「落差」一節。hook **不寫**任何人寫的文件。

| 類別 | 定義 | 給使用者的下一步 |
|---|---|---|
| `codeNotInDoc` | 掃到的模組，5.5 沒寫（只在有 5.5 時才報） | 委派 architect 更新 5.5，或不理它 |
| `docNotInCode` | 5.5 的路徑對不到任何檔案 | 程式已經搬家或刪掉了，文件要跟著改 |

## 5. 說明層（`module-notes.md`）

### 5.1 格式

這是唯一來源，寫成 `project-docs/module-notes.md` 附屬檔的內容。

```markdown
---
based_on: a1b2c3d          # 寫說明時的 HEAD
generated: 2026-11-05
---
| id | 名稱 | 分組 | 說明 | 依據 |
|---|---|---|---|---|
| auth | 登入與權限 | 後端 | 用公司 LDAP 驗證帳號，簽發登入憑證，並檢查每個 API 的角色 | `src/auth/ldap.py` |
```

### 5.2 寫作標準（附屬檔的重點）

- 名稱 ≤ 12 個全形字，說明 ≤ 60 字
- 寫「它替使用者或業務做什麼」，不寫「這個資料夾包含哪些檔案」
- 禁用空洞詞，同 `anti-ai.md` 的文案原則
- 「依據」至少一個真實檔案，而且要在該模組的路徑內
- **不准寫**主機名、IP、連線字串、帳號、客戶名稱、Email（金融客戶）
- 每個模組最多讀 3 個代表檔，每個最多 200 行：進入點、最大的檔、路由檔
- 預估每個模組 3–6k 輸入 token；30 個模組約 100–180k，之後只重寫過期的模組

### 5.3 機器驗證（`overview.sh --check-notes`）

會擋：

- id 不存在於骨架
- 長度超限
- 「依據」的檔案不存在或不在該模組內
- 符合以下樣式：IPv4、`Server=`、`Data Source=`、`password`、`pwd=`、`://` 加帳密、Email
- 表頭不對

post-write 寫入 `module-notes.md` 時執行，有違規就把清單放進 `additionalContext`，沒有違規就完全不輸出。
驗證沒過的那幾列，畫面上當成「沒有說明」。

### 5.4 過期判定與入口

- 腳本用一個 `git diff --name-only <based_on>` 加上工作區改動，把改過的檔對到模組，設 `description.stale`
- `overview.sh --print-path` 多印一行「提示：N 個模組沒有說明、M 個可能過期」
- `/task-status` 收到這行提示時，用 AskUserQuestion 問：全部重寫／只更新過期的 (Recommended)／先不要
- **永遠不自動執行**
- `project.json` 的 `overview.notes: off` 可以完全關掉說明層，提示也一併不印

| Q14 | 反 AI 感：照 `anti-ai.md` 產出後清單逐項對照；`--chg` 紫色只用在「本次改動」這一個語意上，不做漸層 | — | [M] 自檢清單附在階段報告 |

### 6.2 不理想資料下的修法

對應 ADR-003 的根因表。

1. **標籤正規化（腳本端）**：`overview.sh` 把所有來自 md 的標籤去掉 HTML 標籤、`<br\s*/?>` 換成空白、解碼 `&amp;` 之類的實體、壓掉多餘空白。頁面端的 `el()` 再防禦一次
2. **未分組**：不在 `groups` 裡的模組歸到 `_ungrouped`，畫成獨立一欄「未分組」，放在最右邊。所有模組都未分組時就不畫群組框
3. **全圖範圍**：`draw()` 之後用 `world.getBBox()` 加上留白，取代現在只看群組框的算法；小地圖的 viewBox 也用同一個值
4. **連線**：同一欄、距離很遠的兩張卡不再畫成直線穿過中間的卡，改從右側繞出去；邊的標籤不畫在畫布上，只在右側欄列出
5. **SVG 文字截斷**：新增 `fitText(textEl, maxW, maxLines)`，用 `getComputedTextLength` 量寬度，用二分法找截斷點。名稱兩行時卡片高度跟著長高。要等 `document.fonts.ready` 之後才量
6. **卡片列省略**：沒有路徑就不印路徑列，沒有改動就不印改動區，沒有任務就不印任務列。改由頁首的摘要數字和右側欄說明整體缺什麼
7. **任務列**：最多列出 6 個任務 id，其餘寫「＋N」；推斷出來的任務加虛線底線
8. **說明**：縮放 ≥ 55% 時，卡片顯示說明的第一行（截斷）；完整說明、依據檔案、過期標記都在右側欄

### 6.3 驗收方式

## 9. 需要使用者拍板

1. **說明層的同意方式**：程式碼片段會經由 Claude Code 送到 Anthropic，這和平常開發是同一個通道。
   建議做法：每次都由 `/task-status` 問，永遠不自動執行，並提供 `overview.notes: off` 讓不允許的客戶專案整個關掉。這樣可以嗎？
2. **`module-notes.md` 要不要進 git？** 建議進：寫一次要花 100k 以上 token，團隊可以共用；而且 hook 不會背景改它，所以不會弄髒工作區
3. **for-query 的語言和目錄結構**（例如 Python／C#、有沒有 monorepo、大概多少檔）：掃描規則與 fixture 要照它調。
   只需要結構特徵，不要真實名稱
4. **遠端伺服器上怎麼看畫面？** 現在是 `file://`。如果你是 SSH 進伺服器，畫面要在你的瀏覽器開——是用 VS Code Remote（可以用 Live Preview 開遠端檔案）、
   把 `overview/` 複製回本機，還是需要一個「匯出單一 html」的功能？這會影響要不要在階段 5 加匯出
5. **寫程式碼檔也觸發重掃（30 秒內最多一次，背景執行）**可以嗎？不要的話，骨架只會在寫 wbs／plan 或跑 `/task-status` 時更新
6. **codegraph adapter**：同意先不做，等 C#／Java 專案實測依賴邊漏掉三成以上再做嗎？
7. **主題切換**：跟隨系統，再加一個手動切換鈕、記在 localStorage，可以嗎？

## 10. 風險

| # | 風險 | 對策 |
|---|---|---|
| R1 | 自動切出來的模組粒度不符直覺（太細或太粗） | 上限 40 個；`overview.scan.roots`／`depth` 可以覆寫；5.5 有效時以它為準 |
| R2 | regex 誤抓：註解或字串裡的 `import` | 只比對行首樣式；誤差是多一條邊，可以接受，`weight` 低的邊畫淡一點 |
| R3 | 目錄改名讓模組 id 改變，WBS 的對應斷掉 | `wbsUnknownModule` 落差，並提示可能的新 id（同樣的檔案集合） |
| R4 | 模型去 Read `skeleton.json`、data.js | 沿用 R1 舊對策：檔頭寫明「給瀏覽器讀，模型不要讀」；`/task-status` 只印路徑 |
| R5 | 說明裡寫進客戶機密 | `--check-notes` 的樣式擋一層；附屬檔明文禁止；`based_on` 讓人工抽查有依據 |
| R6 | `fitText` 在字型還沒載入完時量錯 | 等 `document.fonts.ready` 之後才量；系統字型不用下載，風險低 |
