## 官方文件查證結果（context7：Claude Code docs 的 hooks reference）

- SubagentStart 輸入有 `agent_id`、`agent_type`；不能阻擋，可回 `additionalContext`
- common input fields：hook 在 subagent 內觸發時帶 `agent_id`／`agent_type`
- PermissionRequest 輸入：`tool_name`、`tool_input`，**沒有 `tool_use_id`**，可選 `permission_suggestions`
- Notification 類型（matcher 值）：`permission_prompt`、`idle_prompt`、`auth_success`、`elicitation_dialog`、`elicitation_complete`、`elicitation_response`。**計畫寫的 `agent_needs_input` 不在官方清單**
- `"async": true`：只限 `type: "command"`、不阻擋、預設逾時 10 分鐘；社群文件與 issue 指出輸出被忽略、不能當閘門
- 待階段 3 探針實測：subagent 內的 PermissionRequest／Notification 是否帶 `agent_id`；SubagentStart 的 `cwd` 是否為 worktree 根；async 在目前版本是否正常

## 與計畫現行文字不一致、需要 planner 同步的地方

1. **事件行多兩個欄位**（ADR-002 第 2 節）：`ms`（毫秒，async 寫入順序不保證，need 的開關要靠 `(t, ms)` 排序）與 `nt`（notification_type，合併 permission_prompt 用）。計畫階段 3 的格式與驗收要補
2. **主 session 的工具事件也要記**（`aid` 為空）。主 session 自己的等批准／AskUserQuestion／寫檔需要；計畫階段 3 的接線本來就沒限定 subagent，只是委派訊息寫「帶 agent_id 的」——ADR 已寫明理由
3. **Bash「第一個詞」要跳過 `NAME=value` 賦值**（`API_KEY=xyz curl` 的第一個詞就是秘密）。計畫階段 3 驗收要加一條
4. **Notification 開啟者清單**拿掉 `agent_needs_input`（除非探針錄到）
5. **伺服器網址帶 token 前綴**（ADR-003 第 1 節）：網址變 `http://127.0.0.1:<port>/<token>/index.html`，身分端點是 `GET /<token>/.serve-id`，`--stop` 走 `POST /<token>/.shutdown`、不靠 pid。計畫階段 4 的 p7／p8 驗收與 task-status 步驟 7 的網址格式要跟著改
6. **選 port 由 Python 自己 bind**，bash 不先探測（避免探測與 bind 之間被搶）；加 `.serve.lock` 防兩個同時起
7. **開瀏覽器**：計畫階段 4 寫「其他只印網址」，但使用者 Q4 選「新起時自動開」、委派訊息也要求 Windows／macOS 用 `start`／`open`。ADR-003 照 Q4：macOS `open`、Windows `cmd //c start "" <網址>`
8. **頁面要處理伺服器已閒置結束**：分頁在背景超過 30 分鐘後回來，輪詢會失敗，頁面應顯示「伺服器已結束，重跑 /task-status」。計畫階段 7 目前沒有這條
9. **計畫第 304 行寫的第 ③ 份 ADR（拆 now.js）作廢**：改為 ADR-001（不拆、128KB）。階段 7 依它的「注意」走不建 now.js 的分支；`files:` 與 p12～p14 的 `now.js` 要拿掉
