# ADR-2026-11-05-007: 架構文件分「人寫」與「地圖資料產生」兩部分；一頁現況與「plan 預計會動」一層都由同一份地圖資料順帶產生

## 背景

專案地圖在兩個實測專案畫不出來或很醜，原因是地圖的骨架讀架構文件的模組表，而那份表不是真實狀態。
ADR-001（已採納）已經把地圖骨架改成掃程式碼（`overview-scan.sh`），架構文件 5.5 降為選配覆寫。
但客戶仍需要一份可交付的架構文件，而手寫的模組表與依賴圖一定會過期（B 的主架構文件 900 行舊文、9 處失效路徑）。
另外，兩個專案都沒有「現在做到哪」的單一頁面：A 的進度散在 5 處、B 的端點數有 5 種寫法——手寫的現況與計數一定過期。
使用者滿意的地圖畫面（現行 `templates/overview/index.html`＋範例資料）已經有 WBS 燈號、★本次任務、git diff 本次改動，
並選擇再加一層「plan 預計會動」。
架構文件裡哪些由人寫、哪些由程式產生？現況頁與 plan 這一層又從哪裡來？

## 決策

**原則：文件裡會過期的部分（模組、依賴、計數、進度）都由地圖的同一份掃描資料產生；人只寫程式碼看不出來的事。**

**1. 架構文件 `docs/architecture.md`**（範本 05 改寫）：

| 部分 | 內容 | 誰寫 |
|---|---|---|
| 1 系統情境 | 誰用、跟哪些外部系統連（C4 第一層的圖＋一張表） | 人（`architect`） |
| 2 技術選型 | 語言、框架、資料庫、部署平台；每列連到對應的 ADR | 人 |
| 3 部署 | 環境、部署單元、上線方式；細節在 `docs/runbook.md`（若有） | 人 |
| 4 模組與依賴 | 模組表＋mermaid 依賴圖，夾在固定標記之間 | **`overview.sh` 產生** |

標記（字串固定，範本與腳本共用；格式比照既有的 `overview:actual`）：

```markdown
<!-- overview:generated:start -->
（此段由專案地圖產生，手改會被覆蓋。改模組名稱或分組請改 `.claude/taskmaster-data/module-notes.md`）
（mermaid：每個分組一個 subgraph，邊取自掃描的 import／http 依賴）
| id | 模組 | 分組 | 路徑 | 檔數 | 路由數 | 說明 |
<!-- overview:generated:end -->
```

- **誰改寫標記區**（使用者 2026-11-05 已確認：接受兩次更新之間落後幾個 commit）：`overview.sh --sync-arch`，只改兩個標記之間、只在主 checkout 執行；沒有標記就不碰檔案、印一行提示。
  呼叫點是 `/verify` 的「文件同步關卡」（主 checkout）與 `/task-status`。**背景重掃不寫它**——hook 不寫模型會 Edit 的檔（既有原則），
  否則會和正在編輯架構文件的模型互相覆蓋，也會在 worktree 平行開發時造成衝突
- 名稱、分組的來源照 ADR-002 的優先序（5.5 → module-notes → 目錄名）；**分組名就是 PRD 功能節的領域名**（ADR-005）
- `overview.sh` 把架構文件當 5.5 覆寫來源讀時，**跳過標記區**（和 `overview:actual` 區塊一樣，免得讀到自己的輸出）。標記區外人寫的 5.5 照舊有效，既有專案不退化
- 新範本**不再有人寫的 5.1 容器圖與 5.5 模組表**；`architect` 設計中、還沒有程式碼的模組寫在 ADR 或 plan，程式碼出現後自動段就會有它

**2. 一頁現況**：`overview.sh` 渲染 `overview.md` 時在最前面放「## 現況」一節（≤ 30 行），`overview.sh --status` 只印這一節，
`/task-status` 印它而不是自己拼，畫面頁首用同一份資料。

| 列 | 來源 |
|---|---|
| 一句話 | `docs/00_brief.md` 的「一句話」 |
| 里程碑進度 | `wbs.md` |
| 進行中（最多 5 個：任務、plan 第 N／M 階段） | `wbs.md`＋plan 的 `current_phase` 與階段數 |
| 阻塞、下一個 | `wbs.md` |
| 最近 14 天完成 | `wbs.md` 完成日 |
| 落差 N 項 | ADR-001 的 drift |

一頁現況是產生物、不進 git；進 git 的摘要仍是 `wbs.md` 的「現況」區（照現行由指令維護）。

**3. 地圖的「plan 預計會動」一層**（使用者已選；屬地圖計畫，ADR-001～003 不改）：

| 資料 | 來源 | 畫面 |
|---|---|---|
| 預計會動的模組 | 本次任務（`.current-task`）plan 的 `files:` glob，對到模組路徑 | 模組卡片外加**虛線框** |
| 實際動了的模組 | 既有的 git diff（相對分岔點） | 照現行（改動標記） |
| 兩者對照 | 既有的 `mismatch`（`declared-not-touched`／`touched-not-declared`） | 右側欄列「預計但沒動」「沒預計卻動了」 |
| plan 進度 | 標題狀態為 🔄 的階段（沒有時用 `current_phase`）、`### 階段 N` 的數量 | 右側欄顯示「plan 第 N／M 階段」；階段平行（ADR-006）時「第 2、3／4 階段」 |

**與文件體系的介面**：這一層只依賴 plan 的 `files:`、`current_phase`、`### 階段 N: 名稱 <狀態>` 標題——ADR-006 保證這三樣格式不變
（ADR-006 新增的「依賴」行寫在標題下一行，不影響解析）。
沒有 plan、或 plan 沒寫 `files:` → 不畫虛線框，其他照常。

**4. 新腳本只有一支**：地圖的 `overview-scan.sh`（ADR-001）。架構文件自動段、一頁現況、plan 疊層都是 `overview.sh` 的新出口，不另開腳本、不加 hook。

## 替代方案

| 方案 | 優點 | 否決理由 |
|---|---|---|
| 由地圖取代架構文件 | 少一份文件 | 客戶需要可交付的架構文件；地圖不進 git |
| 架構文件全人寫（現狀） | 不用改腳本 | 模組表與依賴圖一定過期，地圖正是因此畫不出來 |
| 背景重掃時順便改寫標記區（每次寫程式碼都更新） | 永遠最新 | hook 寫模型會 Edit 的追蹤檔：和模型的編輯互相覆蓋、worktree 平行時必衝突、每次寫檔都產生 diff 噪音 |
| 自動段寫成獨立檔（`docs/architecture-modules.md`） | 不用標記、不怕覆蓋人寫的字 | 多一份文件；客戶拿到的架構文件要一份完整的 |
| 另做一張「開發地圖」 | 開發與總覽分開 | 使用者明確只要一張；plan 疊層加在同一張就夠 |
| 一頁現況另寫 `status.sh` | `overview.sh` 不再變大 | 現況用的資料（WBS、plan、drift）`overview.sh` 已經全部解析過，另寫一支要重複解析 |
| 人寫 `docs/STATUS.md` | GitHub 上看得到 | 就是 A、B 現在的問題：手寫的現況一定過期 |

## 後果

**得到：**
- 架構文件可以交付給客戶，而且模組與依賴那段跟程式碼一致
- `/task-status` 或打開地圖，就看得到做到哪、卡在哪、下一個、這次 plan 預計動哪裡、實際動了哪裡
- 沒有新 hook；新增的只有 `overview.sh` 的三個出口

**犧牲：**
- 自動段只在 `/verify`、`/task-status` 時更新，兩次之間可能落後幾個 commit
- 有人手改標記區，下一次同步就被覆蓋（標記區第一行寫明；改名稱、分組要改 module-notes）
- `overview.sh` 職責再變多。若它超過一份檔該管的範圍，先把「輸出成 md」（現況、架構自動段）拆成同目錄的另一支，不改資料流

**何時該重新考慮：**
- 使用者常抱怨架構文件的自動段落後 → 讓 `/pr` 也呼叫一次 `--sync-arch`
- 多數專案的人寫三節長期空白 → 架構文件降為選配，只留自動段

## 確認方式

- [T] `overview.sh --sync-arch`：有標記 → 只改標記之間、標記外的位元組不變；沒有標記 → 檔案不變、印一行提示；在 worktree 執行 → 不寫
- [T] 架構文件的標記區裡有模組表 → `overview.sh` 解析 5.5 時不把它當覆寫來源；標記區外人寫的 5.5 照舊覆寫
- [T] `overview.sh --status`：fixture 專案輸出 ≤ 30 行，含「進行中」「阻塞」「下一個」「落差」
- [T] 本次任務的 plan `files:` 只有 `src/services/a/**` → 只有該模組 `planned: true`；plan 沒有 `files:` → 所有模組都沒有 `planned`
- [T] plan 的階段 2、3 標題都是 🔄 → `currents[].activePhases` 為 `[2,3]`；都不是 🔄 → `[current_phase]`
- [M] 範例電商（使用者滿意的那份資料）加上一份 plan：預計會動的模組有虛線框、右側欄顯示「plan 第 N／M 階段」，其餘畫面與參考 artifact 相同
