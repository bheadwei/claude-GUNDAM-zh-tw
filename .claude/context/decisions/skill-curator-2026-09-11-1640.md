## 範圍

- **觸發原因**：改 hook 是這個 repo 的日常，但改壞的當下沒有任何回饋——要等下一條指令噴 syntax error 才發現。與上一輪「衝突檔是 live hook → 委派提示靜默失效」同一個家族
- **參考資料**：`context/learned/2026-09-11-gate-blocks-its-own-fix.md`

## 改了什麼

`post-write.sh` 在取得 `FILE_PATH`、確認 `jq` 存在之後插入一段：路徑正規化後比對
`*/.claude/hooks/*.sh`，檔案存在且 `bash -n` 非零 → 用 `additionalContext` 把
stderr 原文貼出來並 `exit 0`。

**位置為什麼在 `.suggest-mode` 與擴充提醒之前**（這是唯一需要判斷的點）：

1. 擴充維護提醒本來就命中 `.claude/hooks/*`，而且它會 `exit 0`。放在它後面 → 語法錯誤永遠不會被報出來
2. `/suggest-mode off` 控的是建議密度；「這支 hook 語法壞了」是檔案狀態的事實，不是建議
3. 沒壞時完全不輸出，所以常態成本是零，不需要靠開關省噪音
