## 第 1 部分：使用案例與風險分級

- 每個 AI 功能填一列；風險等級決定下方 Guardrails 嚴格度與 UX 揭露深度。

| 功能/使用案例 | 輸入資料敏感度 | 決策影響範圍 | 風險等級 | 依據 |
| :--- | :--- | :--- | :---: | :--- |
| [如：客服問答摘要] | [公開/內部/PII] | [僅供參考/影響操作/自動執行] | 低 | 唯讀建議、可人工忽略 |
| [如：風險評分] | [PII] | [影響審核決策] | 中 | 需人工覆核才生效 |
| [如：自動核准/退款] | [PII/財務] | [直接執行動作] | 高 | 高影響 + 不可逆 |

**風險等級定義**：
- **低**：AI 產出僅供參考，人類完全掌控最終決策，錯誤影響小且可逆
- **中**：AI 產出影響決策但有人工審核關卡，錯誤有明確補救路徑
- **高**：AI 可直接觸發不可逆動作或高敏感決策，需最嚴格 guardrail + 揭露

### 3.2 模型升級流程

## 第 5 部分：Guardrails 分層

| 層級 | 目標風險 | 檢查方式 | 延遲預算 | 未通過動作 |
| :--- | :--- | :--- | :--- | :--- |
| L1 確定性檢查 | Prompt Injection / 格式異常 | regex / schema 驗證 | < 10ms | 拒絕並回覆制式訊息 |
| L2 內容分類 | PII 洩漏 / 毒性內容 | 分類器/正則+NER | < 100ms | 遮罩或阻擋輸出 |
| L3 行為控制 | Jailbreak / 過度自主 tool-call | 規則引擎 + 白名單工具集 | < 100ms | 阻擋該次 tool 呼叫，記錄告警 |
| L4 資料完整性 | 檢索污染（RAG） | 來源可信度檢查、簽章驗證 | [依場景] | 標記低信任來源，降權或排除 |

- 交談型應用整體延遲預算目標：[< 200ms]（含 L1-L3 檢查）；超出時優先犧牲非關鍵檢查而非跳過安全檢查。
