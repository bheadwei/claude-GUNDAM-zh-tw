## 0. 使用說明 — 本文件定「為什麼、投入多少」，任務追蹤在 `wbs.md`

本文件結合兩種規劃視角，缺一不可：

- **Appetite（投入上限，源自 Shape Up）**：每個提案先定「願意花多少時間」而非「估計要花多少時間」，時間到就檢視是否繼續投入 — 見第 1 節 Pitch
- **WBS（What）**：拆出要做的工作項目、依賴關係與交付物 — 高階模組見第 3 節，**任務列與狀態只在 `wbs.md`**

**運作原則**：先寫 Pitch 決定「值不值得做、要花多少」，值得做才展開 WBS 細節；WBS 的任務工時**不應超過**對應 Pitch 的 Appetite，超過時應回頭砍範圍（見 Rabbit Holes / No-Gos），而不是無限延長工時。

> **本文件不放任務表。** 任務列、狀態、進度、風險與阻塞的唯一來源是
> `.claude/taskmaster-data/wbs.md`，版面定義在 `.claude/templates/wbs.template.md`。
> 這裡再抄一份任務表，兩邊一定會漂開——本文件只寫 `wbs.md` 裝不下的**規劃脈絡**。

## 1. Pitch（提案）— Shape Up 五要素

> 展開 WBS 前先寫這節。目的：在投入細部拆解前，先確認「問題值得解、方案夠具體、投入有上限」。

| 要素 | 內容 |
| :--- | :--- |
| **Problem（問題）** | [這個提案要解決什麼問題？誰受影響？不做會怎樣？] |
| **Appetite（投入上限）** | [願意投入的時間上限，例：2 週 / 6 週週期。**這是上限不是估計**，到時間就檢視取捨] |
| **Solution（解法）** | [用手繪/文字草圖說明大致解法，粗顆粒度即可，不需完整設計] |
| **Rabbit Holes（風險陷阱）** | [已知可能拖垮時程的細節或未知數，需要提前排除或標記為「先不管」] |
| **No-Gos（不做的事）** | [明確排除在本次範圍外的功能/情境，避免範圍蔓延（scope creep）] |

## 3. WBS 高階模組

只列**模組與它對應的任務編號組、里程碑**，不列任務、不記工時與狀態（那些在 `wbs.md`）。
用途是讓新成員一眼看懂專案的切分方式，以及 `wbs.md` 裡 `13.x` 這種編號是什麼。

| 編號組 | 模組 | 範圍說明 | 主要落在里程碑 |
| :--- | :--- | :--- | :--- |
| 1.x | 專案管理與規劃 | 啟動、需求分析、監控 | M1 |
| 2.x | 系統架構與設計 | 技術架構、資料庫、API 規範 | M1 |
| 3.x | 後端開發 | 基礎架構、核心模組、業務邏輯 | M2 |
| 4.x | 前端開發 | 元件庫、互動、UX | M2 |
| 5.x | 測試與品質保證 | 單元、整合、E2E、效能 | M3 |
| 6.x | 部署與上線 | 環境、生產部署、監控 | M4 |
| 7.x | 文檔與培訓 | 技術文檔、使用者手冊 | M4 |

> 任務工時加總（`wbs.md` 的「預估」）超出對應 Pitch 的 Appetite 時，回到第 1 節檢視 Rabbit Holes / No-Gos，優先砍範圍而非延長工時。

## 7. 執行階段（與 Claude Code 工作流整合）

`wbs.md` 是**專案層級的 backlog（What）**；每個 WBS 任務的**實作藍圖（How）**由 `/plan` 指令產生並持久化。

### 運作方式

1. **`/task-next`** — 從 `wbs.md` 取下一個任務（自動更新狀態為 🔄 進行中，重算「現況」）
2. **`/plan <wbs-id>`** — 為該任務產生實作藍圖，寫入 `.claude/taskmaster-data/plans/<id>-<slug>.md`
   - 計畫檔包含：階段拆解、風險、依賴（技術）、驗收標準
   - `wbs.md` 該任務的「連結」欄會自動加上計畫連結
3. **`/tdd`** — 自動載入當前任務的計畫，按階段 RED-GREEN-REFACTOR 推進；每完成一階段即更新計畫檔狀態
4. **`/verify`** — 讀計畫驗收標準比對測試結果 → PASS 後：
   - `wbs.md` 該任務標為 `✅ MM-DD`
   - 計畫檔歸檔至 `plans/archive/`，連結欄同步改指

### 職責分工（避免重複維護）

| 內容 | 唯一來源 |
|---|---|
| 任務列、狀態、優先、依賴、預估、負責、進度、風險與阻塞 | **`wbs.md`**（版面：`.claude/templates/wbs.template.md`） |
| 階段拆解、驗收標準、實作細節、帶給下一任務的疑慮 | **Plan 檔**（`plan-format` skill） |
| Appetite（投入上限）、Problem/Solution 脈絡、里程碑交付物 | **本文件** |

### WBS 任務列範例（負責欄、連結欄）

```markdown
| 2.1 | 建立 auth middleware | 🔄 進行中 | 高 | 1.3 | 4h | alice | [計畫](plans/2.1-auth-middleware.md) |
```

「負責」只寫一個小寫人名，未指派 `—`。每格只寫一行；驗證數據、選型理由、阻塞原因該搬去哪，見 `.claude/templates/wbs.template.md` 第 4 節。
