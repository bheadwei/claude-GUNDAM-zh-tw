## 2. CI/CD 流水線

| 階段 | 步驟 |
| :--- | :--- |
| **建置** | 拉取程式碼 → 安裝依賴 → 編譯 → 單元測試 → 產出 artifact（含 SBOM） |
| **測試** | 部署至 staging → 整合測試 → E2E 測試 → 效能測試 → 安全掃描 |
| **部署** | 準備新環境 → 部署應用 → 煙霧測試 → 切換流量 → 清理舊環境 |

---

## 3. 部署檢查清單

### 部署前
- [ ] Code review 通過；所有測試通過（單元/整合/E2E）
- [ ] 安全掃描完成（→ 詳見 13_security_and_readiness_checklists.md）
- [ ] 效能基準達標；DB migration 準備好（如需要）
- [ ] 回滾計畫已記錄；監控告警已配置；團隊已通知

### 部署中
- [ ] 監控部署進度、驗證健康檢查、檢查應用日誌
- [ ] 驗證關鍵功能、監控系統指標

### 部署後
- [ ] 煙霧測試通過；效能指標與錯誤率正常；文檔已更新

## 5. 監控與告警

> 詳細 SLI/SLO/Error Budget/Burn Rate 告警設計 → 詳見 19_observability_and_slo_spec.md，本節僅列基礎設施層指標。

### 關鍵指標

| 類別 | 指標 | 閾值 |
| :--- | :--- | :--- |
| 應用 | 回應時間 P95 | < 500ms |
| 應用 | 錯誤率 | < 0.1% |
| 基礎設施 | CPU 使用率 | < 80% |
| 基礎設施 | 記憶體使用率 | < 85% |
| 基礎設施 | 磁碟使用率 | < 90% |

### 告警規則

| 名稱 | 條件 | 嚴重程度 | 通知方式 |
| :--- | :--- | :--- | :--- |
| 高錯誤率 | error_rate > 1% | Critical | Page on-call |
| 高延遲 | P95 > 1000ms | Warning | Slack |
| 資源耗盡 | CPU/Mem > 90% | Warning | Slack |

## 6. 回滾流程

### 自動回滾觸發
- 錯誤率超過閾值 / 回應時間顯著退化 / 健康檢查失敗

### 手動回滾步驟
1. 確認最後一個穩定版本
2. 執行回滾（e.g., `kubectl rollout undo deployment/app`）
3. 驗證回滾成功、監控應用健康
